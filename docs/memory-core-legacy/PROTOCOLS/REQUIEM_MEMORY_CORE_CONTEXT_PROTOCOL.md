# REQUIEM MEMORY CORE CONTEXT PROTOCOL

Version: 0.1

Document Type:
AI Context Generation Protocol

Purpose:
Define how REQUIEM Memory Core creates, maintains and provides project context packages for humans and AI systems.

---

# 1. CONTEXT SYSTEM PURPOSE

REQUIEM Memory Core Context System exists to preserve project understanding between:

- AI sessions;
- development sessions;
- team members;
- project stages.

Its purpose is not storing all project information.

Its purpose is providing the right information at the right moment.

---

# 2. CORE PRINCIPLE

A context package must answer five fundamental questions:


What is REQUIEM?

Where is the project now?

Why is it built this way?

What happened before?

What should happen next?


---

# 3. CONTEXT PACKAGE IDENTITY

The generated context package is a temporary representation of project understanding.

It is not the source of truth.

Source of truth remains:

- project files;
- memory objects;
- approved decisions;
- documented architecture.

The context package is an interface between Memory Core and AI systems.

---

# 4. CONTEXT PACKAGE STRUCTURE

A standard context package contains:


REQUIEM_CONTEXT

├── Identity

├── Current State

├── Architecture Summary

├── Active Decisions

├── Recent Important Events

├── Current Tasks

├── Restrictions

└── Recovery Information


---

# 5. IDENTITY SECTION

Purpose:

Explain what REQUIEM is.

Contains:

- project purpose;
- core principles;
- long-term direction.

Example:


REQUIEM is a premium desktop tactical environment and AI-assisted modding platform.

Games are environments.
REQUIEM is the intelligence and orchestration layer above them.


---

# 6. CURRENT STATE SECTION

Purpose:

Explain the current project position.

Contains:

- current phase;
- completed milestones;
- active work;
- blockers;
- next actions.

Example:


Phase:

Phase 1

Status:

Architecture preparation

Next:

Core Skeleton definition


---

# 7. ARCHITECTURE SUMMARY SECTION

Purpose:

Provide the current system model.

Contains:

- major layers;
- important boundaries;
- structural rules.

Example:


Application Shell

↓

Intelligence Boundary

↓

Operations Runtime

↓

Game Adapters


---

# 8. ACTIVE DECISIONS SECTION

Purpose:

Preserve important reasoning.

Contains:

- active decisions;
- reasons;
- consequences.

Example:


Decision:

S.T.A.L.K.E.R. 2 remains an adapter.

Reason:

REQUIEM must remain independent from a single game.


---

# 9. RECENT EVENTS SECTION

Purpose:

Provide recent project history.

Contains only meaningful events.

Examples:

- completed phases;
- created systems;
- architectural changes.

The context package must avoid unnecessary noise.

---

# 10. CURRENT TASK SECTION

Purpose:

Explain what should happen next.

Contains:

- active objective;
- immediate next actions;
- unresolved questions.

Example:


Current task:

Design REQUIEM Memory Core.

Next:

Define implementation architecture.


---

# 11. RESTRICTIONS SECTION

Purpose:

Prevent incorrect actions.

Contains:

- forbidden approaches;
- protected decisions;
- architectural boundaries.

Example:


Do not:

make REQUIEM S.T.A.L.K.E.R. only;
mix runtime and UI logic;
remove historical decisions.

---

# 12. RECOVERY SECTION

Purpose:

Provide restoration information.

Contains:

- latest stable checkpoint;
- previous milestone;
- recovery location.

Example:


Latest Stable Checkpoint:

CP-001

State:

Documentation foundation complete.

---

# 14. INFORMATION PRIORITY

Not all information enters the context package.

Priority:

## Critical

Always included:

- identity;
- architecture principles;
- important decisions.

---

## Important

Included when relevant:

- phase state;
- milestones;
- active systems.

---

## Normal

Included only when needed:

- technical details;
- temporary information.

---

# 15. AI USAGE RULES

AI systems receiving context must understand:

The package is a starting point, not unlimited authority.

AI should:

- use context;
- verify against reality;
- ask when information is missing.

AI should not:

- invent missing history;
- replace decisions;
- ignore project restrictions.

---

# 16. FUTURE AUTOMATION

Future versions may support:

- automatic context generation;
- context optimization per AI model;
- task-specific context packages;
- IDE integration;
- REQUIEM administration interface.

---

# 17. FINAL PRINCIPLE

The purpose of the Context System:

> A project should never depend on a lost conversation to remain understandable.

REQUIEM Memory Core exists so that understanding survives.
