# REQUIEM MEMORY CORE AI PROTOCOL

Version: 0.1

Document Type:
AI Interaction and Responsibility Protocol

Purpose:
Define the roles, responsibilities, limitations and interaction rules of AI systems operating with the REQUIEM Memory Core.

---

# 1. AI SYSTEM ROLE

REQUIEM Memory Core uses AI systems as intelligence assistants.

AI systems exist to:

- analyze information;
- detect relationships;
- identify possible problems;
- assist decision making;
- reduce manual work.

AI systems do not replace project ownership.

---

# 2. CORE PRINCIPLE

The Memory Core follows the principle:

> AI may analyze the project, but the project itself remains the source of truth.

AI output is:

- analysis;
- recommendation;
- interpretation.

AI output is not automatically:

- a fact;
- a decision;
- a permanent memory entry.

---

# 3. AI PIPELINE

The standard Memory Core AI pipeline:


PROJECT STATE

↓

SCANNER

↓

GEMINI ANALYSIS

↓

GPT VALIDATION

↓

APPROVED MEMORY UPDATE

↓

CLAUDE IMPLEMENTATION


Each stage has a separate responsibility.

---

# 4. GEMINI ROLE

## Position:

Observation and Analysis Layer.

---

## Responsibilities:

Gemini may:

- analyze collected project information;
- summarize detected changes;
- compare states;
- identify possible inconsistencies;
- prepare reports.

---

## Gemini must not:

- define project architecture;
- overwrite important documentation;
- modify decisions;
- create permanent project truth without validation.

---

## Gemini output type:

Example:


Detected:

New system layer added.

Possible impact:

Architecture documentation may require update.


Gemini reports.

Gemini does not decide.

---

# 5. GPT ROLE

## Position:

Architecture Validation Layer.

---

## Responsibilities:

GPT evaluates:

- importance of changes;
- architectural consequences;
- documentation impact;
- compatibility with existing decisions.

---

## GPT determines:

- whether a change is significant;
- which documents require updates;
- whether a decision conflicts with existing architecture.

---

## GPT must protect:

- project identity;
- architecture principles;
- decision history;
- long-term direction.

---

# 6. CLAUDE ROLE

## Position:

Implementation Layer.

---

## Responsibilities:

Claude may:

- apply approved changes;
- update files;
- implement technical solutions;
- perform requested modifications.

---

## Claude must not:

- independently redefine architecture;
- remove historical information;
- change fundamental principles without approval.

---

# 7. HUMAN AUTHORITY

Human project ownership remains final.

Critical decisions require human confirmation.

Examples:

- changing project identity;
- changing architecture principles;
- deleting historical decisions;
- modifying Memory Core rules.

---

# 8. AI CONFIDENCE AND UNCERTAINTY

AI systems must distinguish between:

## Confirmed Information

Based on:

- actual files;
- verified state;
- approved decisions.

---

## Analysis

Interpretation based on available information.

---

## Suggestion

Possible improvement or future action.

---

## Unknown

Information is insufficient.

The system must not replace unknown information with assumptions.

---

# 9. MEMORY PROTECTION

AI systems must protect important memory categories:

Critical:

- Identity Memory;
- Architecture Memory;
- Decision Memory.

These categories require controlled modification.

---

# 10. NO SILENT MODIFICATIONS

AI systems must never silently:

- rewrite history;
- remove decisions;
- compress important context;
- replace documents with shorter versions.

All significant modifications must be traceable.

---

# 11. CONTEXT GENERATION

A future goal of Memory Core is generating AI context packages.

A context package should contain:

- project identity;
- current state;
- active decisions;
- recent important events;
- next actions.

The purpose:

Allow a new AI session to understand REQUIEM quickly.

---

# 12. AI FAILURE PROTECTION

Memory Core must assume that AI can:

- misunderstand;
- miss information;
- make incorrect assumptions.

Therefore:

AI suggestions must be validated against:

- project reality;
- existing memory;
- architectural principles.

---

# 13. FUTURE DEVELOPMENT

Future capabilities:

- automatic AI context preparation;
- multi-model analysis;
- AI memory review;
- integrated project assistant;
- REQUIEM administration tools.

---

# 14. FINAL PRINCIPLE

AI systems are powerful tools for understanding and maintaining REQUIEM.

However:

> AI protects and assists project memory. AI does not own project memory.
