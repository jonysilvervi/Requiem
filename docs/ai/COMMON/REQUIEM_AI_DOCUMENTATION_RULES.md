# REQUIEM AI DOCUMENTATION RULES

Version: 1.0 Draft

Document Type:
Documentation Governance Rules

Purpose:
Define how REQUIEM documentation stays synchronized with development.

---

# 1. DOCUMENTATION AS SYSTEM MEMORY

Documentation is a permanent memory layer of REQUIEM.

Code describes implementation.

Documentation describes:

- purpose;
- architecture;
- decisions;
- current state.

---

# 2. WHEN DOCUMENTATION MUST CHANGE

Documentation review is required after:

- architectural changes;
- new systems;
- completed phases;
- responsibility changes;
- major refactoring.

---

# 3. DOCUMENTATION TYPES

## Current State

Answers:

"What exists now?"

---

## Architecture

Answers:

"How is the system structured?"

---

## Decisions

Answers:

"Why was it built this way?"

---

## AI Context

Answers:

"How should AI work with this project?"

---

# 4. NO SILENT DRIFT

If code and documentation disagree:

The difference must be analyzed.

Do not ignore documentation drift.

---

# 5. CHANGE PROCESS

Recommended flow:

Implementation

↓

Review

↓

Documentation Impact Check

↓

Update Required Documents

↓

Record Decision if needed

---

# 6. FUTURE AUTOMATION

REQUIEM may use:

- Git history;
- change reports;
- AI assistants;
- automated checks;

to reduce manual documentation maintenance.

---

# END OF RULES
