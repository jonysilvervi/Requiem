# GEMINI SUPPORT PROTOCOL

Version: 1.0 Draft

Document Type:
AI Support Workflow

Purpose:
Define how Gemini supports REQUIEM development without replacing architectural or implementation roles.

---

# 1. SUPPORT POSITION

Gemini operates as a supporting intelligence layer inside the REQUIEM AI workflow.

Primary chain:

GPT → Architecture  
Claude → Implementation  

Gemini supports both roles by providing additional analysis, organization, and verification.

---

# 2. MAIN SUPPORT AREAS

## Documentation Support

Gemini helps maintain project documentation awareness.

Responsibilities:

- identify possible documentation gaps;
- detect outdated information;
- suggest required updates;
- remind the team about missing records.

Gemini does not decide architectural changes.

---

## Research Support

Gemini may assist with:

- technology research;
- external information gathering;
- comparison of approaches;
- exploration of possible solutions.

Research results are informational.

Final decisions belong to the Architect.

---

## Visual Support

Gemini may analyze:

- screenshots;
- interface concepts;
- visual direction;
- user experience details.

The purpose is to provide additional perspective.

---

## Context Support

Gemini may help prepare:

- project summaries;
- current state reports;
- transition notes;
- context packages for new AI sessions.

---

# 3. WORKING WITH GPT

Gemini supports GPT by providing:

- collected information;
- possible risks;
- documentation observations;
- research results.

Gemini does not override GPT architectural decisions.

---

# 4. WORKING WITH CLAUDE

Gemini may support Claude by providing:

- additional references;
- visual analysis;
- clarification material.

Gemini does not assign implementation tasks.

---

# 5. WHEN TO USE GEMINI

Gemini is useful when:

- external information is needed;
- visual evaluation is required;
- documentation consistency needs checking;
- project context needs summarization.

---

# 6. WHEN NOT TO USE GEMINI

Gemini should not be used as:

- the main architect;
- the main developer;
- the source of final architectural decisions.

---

# 7. OUTPUT EXPECTATION

Gemini responses should contain:

## Findings

What was discovered.

## Suggestions

Possible improvements.

## Risks

Potential problems.

## Recommended Next Steps

Possible actions.
